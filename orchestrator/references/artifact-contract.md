# 产物契约与进度推断

编排器靠"看文件"判断做到哪一步。本文件定义文件长什么样、怎么认。

## 一、产物契约表

| 步 | 文件名 | 正则 | 必含章节（冻结） | 最小体量 |
| --- | --- | --- | --- | --- |
| S1 | `[系统]需求功能清单.md` | `^(.+)需求功能清单\.md$` | 系统描述 / 核心功能 / 加分功能 / 被舍去的功能 | 800 B |
| S2 | `[系统]硬件选型清单.md`<br>`[系统]硬件选型清单（PCB版）.md` | `^(.+)硬件选型清单(（PCB版）)?\.md$` | 选型依据 / 核心硬件清单 / 选型说明 | 600 B |
| S3 | `[系统]功能拆解文档.md` | `^(.+)功能拆解文档\.md$` | 拆解依据 / **二、硬件模块清单** / 模块卡片 / 模块关系图 | 1.2 KB |
| S4 | `[系统]硬件搭建文档.md` | `^(.+)硬件搭建文档\.md$` | 搭建依据 / **四、引脚分配速查** / **六、接线总表** / 接线注意事项 | 1.2 KB |
| S5 | `[系统]模块编程记录.md` | `^(.+)模块编程记录\.md$` | 输入锁定结果 / 模块实施顺序表 / 逐模块验证记录 | 1 KB |
| S6 | `[系统]功能联调报告.md` | `^(.+)功能联调报告\.md$` | 追溯矩阵 / 主控逻辑联调 / 云平台自检 / 遗留问题 | 1.5 KB |

**加粗的章节是下游依赖的关键字段**：
- S3 的「二、硬件模块清单」→ S5 读模块顺序
- S4 的「四、引脚分配速查」→ S5 读引脚
- S5 的「模块实施顺序表」→ S6 读追溯依据

章节标题变了，链路就断了。**若用户手工改过标题，降级为语义理解并在方案卡里说明"本次按语义解析，可能漏项"，不要直接中断。**

## 二、系统名称提取

同一项目的 6 个文件共享同一前缀 `[系统]`。推断步骤：

1. 扫**项目根**（当前工作目录）**一层**（不递归）。项目根是变量，不是固定的方法论仓库路径
2. **排除**：`AI-Skill/`、`.workbuddy/`、任何目录
3. 对每个 `.md` 套上面 6 条正则，提取捕获组得到前缀
4. 按前缀分组计数

## 三、进度推断伪代码

```
function infer_step(root):
    ledger = read(root + "项目进度台账.md")
    if ledger exists:
        proj = pick_project_section(ledger)      # 多项目时按用户所指或唯一节
        step = proj.current_step
        if artifact_exists_and_valid(step, proj.system_name):
            return step                           # R1 命中
        # 台账与文件矛盾 → 落到 R2 重新扫

    files = scan_one_level(root, exclude=["AI-Skill", ".workbuddy"], only_files=True)
    groups = group_by_regex_prefix(files)         # {system_name: {S1:path, S3:path, ...}}

    if len(groups) == 0:  return "S1"             # R5
    if len(groups) > 1:   return ASK_USER(groups) # R3 多项目，必须问

    name, found = only_group(groups)
    for step in ["S6","S5","S4","S3","S2","S1"]:  # 从后往前找最大完成步
        if step in found:
            if is_complete(found[step]):          # R4 校验体量与章节
                return next_step(step)
            else:
                return HALF_DONE(step, missing_sections(found[step]))
    return "S1"
```

## 四、is_complete 的三道校验

一个文件"存在"不等于"做完了"：

1. **体量**：小于表里的最小体量 → 判半成品
2. **章节**：缺必含章节（尤其加粗那两个）→ 判半成品，指出缺什么
3. **占位符残留**：仍含 `[模块1]`、`[系统名称]`、`[引脚]` 这类模板占位 → 判未填完

## 五、多项目并存的注意事项

| 情况 | 处理 |
| --- | --- |
| 只有一组前缀 | 直接用 |
| 多组前缀，用户说了项目名 | 按名字模糊匹配 |
| 多组前缀，用户没说 | **必须问**，列出候选让他选 |
| 两个项目前缀相同 | 立即提示改名，否则永久混淆 |
| 旧项目想归档 | 建议建 `归档/` 子目录移入（会脱离扫描范围） |

## 六、台账与产物的一致性维护

| 事件 | 台账动作 |
| --- | --- |
| 某步完成 | 该步状态改 ✅，填完成日期，"当前步骤"指向下一步 |
| S5 每完成一个模块 | "当前步骤"改 `S5 模块k/N` |
| 用户要求回退 | 被回退步状态改 🔄，在其后各步改 ⬜，记录原因 |
| 用户改了某个决策 | 写入「关键决策记录」，标影响范围 |
