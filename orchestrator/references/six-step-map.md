## S5 模块编程

| 项 | 内容 |
| --- | --- |
| **Entry** | **S3 与 S4 都存在**（硬依赖，缺一不可） |
| **下游 skill** | `.../mcu-module-programming/SKILL.md` → 内部逐模块调 `.../stm32-driver/SKILL.md` |
| **子步骤** | ① 输入锁定（读模块顺序 + 读引脚表 → 合成实施顺序表）→ ② 工程前置检查（库类型/Module 目录/CMake/延时打印）→ ③ 逐模块循环体（**先只做本地模块**：方案卡→生成→CMake 登记→静态自检→单模块验证→记状态）→ ④ **本地闭环验收：生成不含通信的本地 main.c，拔掉 WiFi 仍能完整运行** → ⑤ 通信模块单独验证 → ⑥ 接入上报与下行并复测本地无退化 → ⑦ 交付前总检 |
| **产物** | `[工程]/Module/bsp_*.c` `.h`、`[工程]/Core/Src/main.c`、`[系统]模块编程记录.md` |
| **Exit 判据** | 记录表里 N 个模块状态全 ✅ 或 ⚠️ 已判定可接受；**阶段一验收通过（拔掉 WiFi 本地能跑完整链路）**；接入通信后本地功能无退化；`MODULE_TEST` 已置 0 |
| **课件** | 08 工程搭建、09–12 四个模块、13 主控逻辑 |
| **链路的命门** | **引脚不反问用户**——从 S4 的「四、引脚分配速查」直接取；取不到就停下要缺口清单，绝不猜 |
| **编译烧录** | **不做**。用户自己编译烧录后回报现象 |
| **常见失败** | 跳号做模块；问用户引脚（等于断链）；`while(1)` 用长阻塞 |

## 步骤间的"连带失效"关系

改动某一步后，哪些后续步骤需要重做：

| 改动 | 连带失效 | 说明 |
| --- | --- | --- |
| S1 加/删功能 | S2 → S3 → S4 → S5 → S6 | 影响最大，几乎全部重走 |
| S2 换型号 | S4 → S5（部分）→ S6 | 引脚与驱动可能要改 |
| S2 换搭建方式（面包板↔PCB） | S4（模板换） | 引脚基本不变 |
| S3 改模块划分 | S5 → S6 | 模块顺序变了，编程顺序和记录全变 |
| S4 改引脚 | S5 的引脚宏 → S6 | 只需改对应宏定义，但必须重测该模块 |
| S5 改某模块驱动 | S6 | 该模块相关用例重测 |

**编排器职责**：用户提出改动时，主动告知连带影响范围，并在台账「关键决策记录」里写下影响。
