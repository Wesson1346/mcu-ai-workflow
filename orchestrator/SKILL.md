# 单片机项目总编排（六步法）

## Overview

用户脑子里有一个想法（"我想做个智能温控风扇"），最终手上有一个能跑的系统。
中间要经过六步，每步都有固定的产物和验收标准。

**这个 skill 的职责不是自己写全部内容，而是：判断当前该做哪一步 → 出方案卡 → 用户确认 → 调用对应 skill → 校验产物 → 记录进度 → 进入下一步。**

## 六步状态机

| 步 | 名称 | 下游 skill（相对 `{{AI_SKILL_ROOT}}/`） | 产物（项目根目录） | 完成判据 |
| --- | --- | --- | --- | --- |
| S1 | 需求分析 | `mcu-requirement-analysis/` | `[系统]需求功能清单.md` | 含「核心功能 / 加分功能 / 被舍去的功能」三节 |
| S2 | 硬件选型 | `mcu-hardware-selection/` | `[系统]硬件选型清单.md`（PCB 加「（PCB版）」） | 有核心硬件清单表 + 搭建方式已明确 |
| S3 | 功能拆解 | `mcu-functional-decomposition/` | `[系统]功能拆解文档.md` | 有模块清单表，卡片数 = 硬件模块数 |
| S4 | 硬件搭建 | `mcu-hardware-building/` | `[系统]硬件搭建文档.md` | 有「四、引脚分配速查」与「六、接线总表」，无重复引脚 |
| S5 | 模块编程 | `mcu-module-programming/`（内部逐模块调 `stm32-driver/`） | `Module/bsp_*.c/h` + `main.c` + `[系统]模块编程记录.md` | N 个模块状态全 ✅ + **本地闭环验收通过**（拔掉 WiFi 仍能完整运行） |
| S6 | 功能联调 | `mcu-integration-testing/` | `[系统]功能联调报告.md` | 追溯矩阵每行有实测结果 + 云自检 5 项有结论 |

依赖关系：S2 需 S1；S3 需 S1+S2；S4 需 S2 或 S3；**S5 硬依赖 S3 与 S4**；S6 需 S5 记录。
每步的详细 entry/exit、子步骤、对应课件章节见 `references/six-step-map.md`。

## 执行节奏：每步先给方案、确认后执行

**这是本 skill 最重要的行为约束。**

对每一步，先输出一张「步骤方案卡」，等用户回复确认后才动手写文件。
未确认前**不得创建或修改任何项目文件**。

方案卡固定 7 个字段（模板与 6 个示范见 `assets/step-plan-card.md`）：

1. **读入**：本步会读哪几份已有文档
2. **本步目标**：≤3 条
3. **关键决策点**：≤3 个，表格给出「决策项 / 我的建议 / 为什么」
4. **将产出**：绝对路径 + 文件名
5. **需要你回答**：≤3 个问题；**能默认的不问，能推断的不问**
6. **验收方式**：用户怎么判断这步做对了
7. **下一步预告**：一句话

用户说「确认」「可以」「按你说的做」→ 执行本步。
用户说「不用问了 / 直接做」→ 切换为**批量方案卡**（S1–S4 的卡一次列完），
仅本轮会话有效，并在进度台账里记一笔「快速模式」。

> 注意：下游 skill 内部也有自己的子步确认（如需求分析三步法）。这不冲突：
> 编排器的确认是"这一步做不做、大致怎么做"，下游 skill 的确认是"这一步内部每个子环节"。
> 用户嫌烦时可以把下游子步合并，但不能跳过编排器的步骤确认。

## 进度追踪：先看文件，再看台账

### 项目根目录（可变，不要写死）

**项目根 = 当前工作目录**，产物直接放这个文件夹的根，不建子目录。

| 概念 | 路径 | 会不会变 |
| --- | --- | --- |
| **方法论根** | `{{AI_SKILL_ROOT}}/` | **固定**，不随项目移动 |
| **项目根** | 你当前打开的文件夹（如 `D:/我的毕设/`） | 每个项目不同 |

规则：

- 开工前先确认一次项目根，并在方案卡「将产出」里写**完整绝对路径**
- 用户说"在 D:/某处 开发" → 就用那个路径，不要默认写回方法论仓库
- **绝不要把项目产物写进 `AI-Skill/`**，那是方法论仓库，不是工作区
- 方法论仓库全世界只有一份，**不要为了换项目去复制它**——复制会产生多份不同步，
  以后改一次 skill 要改 N 处

### 台账文件

**项目根下的 `项目进度台账.md`**（跟着项目走，整个文件夹可以拷走）。模板见 `assets/progress-ledger-template.md`。

- 一个项目根只放一个项目 → 直接记，不用分节
- 同一个根下有多个项目 → 才用 `## 项目：[系统名称]` 分节
- 台账**不在方法论仓库里**，每个项目各自一份

### 判断"现在该做哪一步"的推断顺序

按 R1–R5 **短路**执行，命中即停：

| 规则 | 做法 | 结果 |
| --- | --- | --- |
| **R1** | 读 `项目进度台账.md`，取该项目节的「当前步骤」，**并回验该步产物文件仍存在** | 产物在 → 采用台账结论 |
| **R2** | 无台账或台账与产物矛盾 → 扫项目根目录**一层**（排除 `AI-Skill/`、`.workbuddy/`），按 `references/artifact-contract.md` 的正则分组，取同一前缀的一组 | 按"最大完成步"判定 |
| **R3** | 扫出多个不同前缀 | **停下来问用户是哪个项目**，不要猜 |
| **R4** | 文件存在但过小或缺关键章节 | 判为「半成品」，在方案卡里指出缺什么 |
| **R5** | 什么都没有 | 从 S1 开始 |

**铁律：产物文件是真相，台账只是加速。** 台账说做完 S4 但 `硬件搭建文档.md` 不存在 → 以文件为准判为 S3 完成。

推断出的结果**必须告诉用户并等确认**，不允许静默续做。
用户说"继续上次项目"时，先输出：「检查到已完成 S1–S4，建议从 S5 模块编程开始（依据：4 份文档齐全）」再等确认。

## 工具链基线（全局生效，覆盖下游 skill 的旧写法）

- **IDE**：AI IDE（CodeBuddy / Qoder / VS Code 系）+ **STM32Cube 扩展**（内含 CubeMX）
- **工程**：CMake + Ninja，目录含 `Core/Inc`、`Core/Src`、`Drivers/`、`cmake/`、`CMakeLists.txt`、`*.ioc`
- **库**：**HAL**（LL 按 HAL 处理）；标准库仅当用户明确说明是遗留工程
- **驱动目录**：`Module/`，并挂进 CMake（见 `references/toolchain-baseline.md`）
- **编译与烧录**：**不写**。由用户自有工具完成，流程只要求用户回报现象
- **三处 HAL 写法**（原 skill 是标准库写法，必须换算）：
  - `DelayUs(unsigned short)` / `DelayMs(unsigned short)` —— HAL 无微秒延时，需自实现
  - `UsartPrintf(USART_DEBUG, ...)` —— 基于 `HAL_UART_Transmit` 自封装
  - `__HAL_AFIO_REMAP_SWJ_NOJTAG()` —— 不是 `GPIO_PinRemapConfig(...)`

课件第 8 篇讲的是 Keil，与本基线不同；`course-notes/08-project-setup.md` 已给出换算表。

## 两种降级路径

### 路径 A：单步直达

用户说「只帮我分配引脚」「直接给我写 DHT11 驱动」——不要重跑全流程。

1. 检查该步的**前置产物**是否存在
2. 有 → 直接执行该步
3. 无 → 给三个选项：
   - 补做前置步骤（推荐，说明为什么）
   - 用户自己粘贴前置内容（功能清单/引脚表等文本）
   - 简化硬做，并在产物头部标注「缺少 X 前置，以下内容基于假设」
4. 做完该步后**不自动进下一步**，告知用户可继续哪一步

### 路径 B：用户已有部分文档

1. **命名对齐**：用户文件名可能不标准。不改用户文件，建议另存为标准名，或记下映射关系
2. **格式体检**：只读检查是否含该步必需的章节（对照 `references/artifact-contract.md`）
3. **可修** → 询问是否补章节；**不可修** → 带风险进入下一步，并在台账记风险

## 常见意图路由

| 用户说 | 该做什么 |
| --- | --- |
| 「我想做个 XX」「帮我做个单片机项目」 | 从 S1 起，先出方案卡 |
| 「继续上次的项目」 | 走 R1–R5 推断，报告结果并等确认 |
| 「我要改需求 / 加个功能」 | 回 S1 改清单，然后提示 S2–S4 可能连带失效 |
| 「换方案 / 板子改了」 | 回 S2（可能到 S3），明确告知下游影响 |
| 「帮我看下代码为什么不对」 | 先判断是 S5 还是 S6 的问题，按回退路由表定位 |
| 「只帮我做 XX」 | 走路径 A |
| 「这个项目做完了」 | 检查 S6 报告是否齐全，提醒清理调试代码 |

## 禁止事项

- ❌ **确认前不动手**：用户没回确认，不创建、不修改任何项目文件
- ❌ **不跳步**：S5 必须有 S3 的模块顺序和 S4 的引脚表；缺了就停下补，不要凭感觉编
- ❌ **不一次列完六步**：第一次响应只出当前这一步的方案卡（用户明确要"快速模式"除外）
- ❌ **不反问已确定的信息**：引脚在 S4 已定、模块顺序在 S3 已定，S5 不许再问
- ❌ **不写编译烧录指令**：不出现 Keil、`.uvprojx`、下载器操作步骤
- ❌ **不编造课件内容**：`course-notes/` 是摘要级，需要原文细节就让用户去 IMA 看
- ❌ **不静默覆盖**：同名文件先问是否覆盖或加日期后缀
