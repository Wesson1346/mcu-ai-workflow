# 步骤方案卡模板

编排器在每一步开工前必须输出一张方案卡。**用户回复确认前不得写任何文件。**

> `[项目根]` = **会话的当前工作目录**（如 `D:/我的毕设/`），**不是**方法论仓库
> `{{AI_SKILL_ROOT}}/`。方案卡里要写**完整绝对路径**，让用户一眼看出文件落在哪。

## 通用模板

```markdown
### 第 N 步：[步骤名称] — 方案

**① 读入**
- `[已有文档1]`（若无写「无，本步从零开始」）

**② 本步目标**
1. [目标1]
2. [目标2]
3. [目标3]

**③ 关键决策点**

| 决策项 | 我的建议 | 为什么 |
| --- | --- | --- |
| [决策1] | [建议] | [理由] |
| [决策2] | [建议] | [理由] |

**④ 将产出**
- `[项目根]/[系统名称][产物名].md`

**⑤ 需要你回答**
1. [问题1]
2. [问题2]

> 这些你不回答我也能按建议默认推进，只是结果可能不是你想要的。

**⑥ 验收方式**
[怎么判断这步做对了，1–2 句]

**⑦ 下一步**
[N+1 步名称]——[一句话说明为什么是它]

---
确认无误请回复「确认」，或告诉我要改哪里。
```

## 硬性约束

| 字段 | 上限 | 规则 |
| --- | --- | --- |
| 读入 | — | 只列真的会读的文件 |
| 目标 | 3 条 | 超过说明这步该拆 |
| 关键决策点 | 3 个 | 只列**会影响后续步骤**的；无关紧要的不列 |
| 需要你回答 | 3 个 | **能默认的不问，能推断的不问** |
| 全卡长度 | 40 行内 | 太长用户不看 |

## 6 个按步实例

### S1 需求分析

```markdown
### 第 1 步：需求分析 — 方案

**① 读入**：无（从你的想法开始）

**② 本步目标**
1. 把「我想做个 XX」整理成一段具体描述
2. 生成并按核心/加分分类的功能清单
3. 逐条取舍，确定最终做什么

**③ 关键决策点**

| 决策项 | 我的建议 | 为什么 |
| --- | --- | --- |
| 项目定位 | 课程设计 / 毕设 / 自己练手 | 决定功能取舍的松紧，课设通常 2 周内要能交付 |
| 是否含云平台 | 先不含，S6 再评估 | 云平台会显著拉长周期，先保证本地闭环 |

**④ 将产出**
- `[项目根]/[系统名称]需求功能清单.md`

**⑤ 需要你回答**
1. 这个项目是课设/毕设/自己玩？大概能做多久？
2. 有没有必须实现的功能（老师要求/自己执念）？

**⑥ 验收方式**
清单里每条功能都能说清「用什么实现、什么条件下做什么」，且被舍去的功能有理由。

**⑦ 下一步**
硬件选型——有功能清单才能定型号。
```

### S2 硬件选型

```markdown
### 第 2 步：硬件选型 — 方案

**① 读入**：`[系统]需求功能清单.md`

**② 本步目标**
1. 每个功能映射到一个硬件型号
2. 确定搭建方式（面包板 / PCB）
3. 输出硬件清单（只选型号，不分配引脚）

**③ 关键决策点**

| 决策项 | 我的建议 | 为什么 |
| --- | --- | --- |
| 搭建方式 | 面包板 | 调试期可改可换；定稿后再考虑 PCB |
| 主控 | STM32F103C8T6 | 资料最多、教程同款、外设够用 |

**④ 将产出**
- `[项目根]/[系统]硬件选型清单.md`

**⑤ 需要你回答**
1. 面包板还是打 PCB 板？
2. 有没有手上已有的模块必须用上？

**⑥ 验收方式**
清单能直接拿去下单，不缺公共件（主控、下载器、电源/接线）。

**⑦ 下一步**
功能拆解——把功能视角换成硬件模块视角。
```

### S3 功能拆解

```markdown
### 第 3 步：功能拆解 — 方案

**① 读入**：`[系统]需求功能清单.md`、`[系统]硬件选型清单.md`

**② 本步目标**
1. 提取硬件模块，编号按「编程实施顺序」而非需求顺序
2. 每个模块写四要素卡片（名称/型号/功能/验证方法）
3. 画模块关系图

**③ 关键决策点**

| 决策项 | 我的建议 | 为什么 |
| --- | --- | --- |
| 模块编号顺序 | 传感器 → 显示 → 执行器 → 按键 → 报警 → 通信 | 显示兼作调试窗口，必须早做 |
| 模块粒度 | 一模块一硬件 | 保证可独立验证 |

**④ 将产出**
- `[项目根]/[系统]功能拆解文档.md`

**⑤ 需要你回答**
1. （一般无需回答，除非有模块你希望合并/拆分）

**⑥ 验收方式**
模块编号连续、卡片数=硬件数、每个模块的验证方法可观察（能说出具体现象）。

**⑦ 下一步**
硬件搭建——按模块分配引脚。
```

### S4 硬件搭建

```markdown
### 第 4 步：硬件搭建 — 方案

**① 读入**：`[系统]硬件选型清单.md`、`[系统]功能拆解文档.md`

**② 本步目标**
1. 按「先特殊功能后普通 GPIO」分配引脚
2. 做 7 项冲突检查
3. 输出引脚速查表 + 接线总表

**③ 关键决策点**

| 决策项 | 我的建议 | 为什么 |
| --- | --- | --- |
| 调试串口 | USART1（PA9/PA10）保留 | 后续所有调试打印靠它，不能占 |
| 执行器接法 | 按选型清单定（模块化直驱/裸器件+驱动） | 接线方式不同 |

**④ 将产出**
- `[项目根]/[系统]硬件搭建文档.md`

**⑤ 需要你回答**
1. （一般无需回答；除非你已有既定接线想沿用）

**⑥ 验收方式**
引脚表里没有任何引脚重复；PWM 都在定时器通道上；没有占用 SWD 的 PA13/PA14。

**⑦ 下一步**
模块编程——按模块编号逐个生成驱动并验证。
```

### S5 模块编程

```markdown
### 第 5 步：模块编程 — 方案

**① 读入**：`[系统]功能拆解文档.md`（模块顺序）、`[系统]硬件搭建文档.md`（引脚表）

**② 本步目标**
1. 合成「模块实施顺序表」（模块号/引脚/驱动文件/验证现象）
2. 按编号逐个生成驱动、逐个验证，不跳号
3. 全部通过后生成 main.c 主控逻辑

**③ 关键决策点**

| 决策项 | 我的建议 | 为什么 |
| --- | --- | --- |
| 库类型 | HAL（Cube 扩展生成） | 你用的是 AI IDE + Cube 扩展 |
| 验证方式 | `#define MODULE_TEST n` 每次只跑一个模块 | 出错能立刻定位 |

**④ 将产出**
- `[工程]/Module/bsp_*.c` / `.h`（每模块一对）
- `[工程]/Core/Src/main.c`（最后生成）
- `[项目根]/[系统]模块编程记录.md`

**⑤ 需要你回答**
1. 工程建好了吗？路径给我（我要检查 CMake 是否挂了 `Module/`）
2. 编译烧录你自己来，对吧？我只需要你回报看到的现象

**⑥ 验收方式**
记录表里每个模块状态为 ✅；编译无报错（你回报）；每个模块的单测现象符合预期。

**⑦ 下一步**
功能联调——模块都通了，开始测系统级行为。
```

### S6 功能联调

```markdown
### 第 6 步：功能联调 — 方案

**① 读入**：需求清单、拆解文档、搭建文档、模块编程记录

**② 本步目标**
1. 建追溯矩阵（每条需求 → 模块 → 代码 → 用例）
2. 五组系统级用例：阈值上下沿 / 模式切换 / 报警联动 / 上电默认 / 按键
3. 云平台 5 项自检（有云时）+ 输出联调报告

**③ 关键决策点**

| 决策项 | 我的建议 | 为什么 |
| --- | --- | --- |
| 测试顺序 | 本地功能先全过，再测云 | 云问题会掩盖本地问题 |
| 断网重连 | 必测 | 演示现场断网一次就废 |

**④ 将产出**
- `[项目根]/[系统]功能联调报告.md`（含 3 分钟演示脚本）

**⑤ 需要你回答**
1. 有云平台/App 吗？（没有就跳过云自检）
2. 需要演示给老师/评委看吗？（需要我写演示脚本）

**⑥ 验收方式**
追溯矩阵每行都有实测结果；遗留问题如实记录且判定影响。

**⑦ 下一步**
没有下一步——交付。我会提醒你清理调试代码、确认凭据已替换。
```

## 批量方案卡（用户说「不用问了」时）

把 S1–S4 的卡压缩成一张表，一次列完：

```markdown
你说不用逐步确认，那我按下面顺序一次推进到 S4（每步产物仍会单独落文件）：

| 步 | 产物 | 我的关键决定 |
| --- | --- | --- |
| S1 需求 | `XX需求功能清单.md` | 定位：[X]；功能砍到 [N] 项 |
| S2 选型 | `XX硬件选型清单.md` | 面包板；主控 STM32F103C8T6 |
| S3 拆解 | `XX功能拆解文档.md` | 模块顺序：传感器→显示→执行器→按键→报警 |
| S4 搭建 | `XX硬件搭建文档.md` | USART1 留给调试；PWM 用 TIM 通道 |

S5 会在每个模块停下让你验证（这步没法批量）。
有异议现在说，否则我开始跑。
```

批量模式**仅本轮会话有效**，并写入台账「快速模式：是」。
