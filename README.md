# MCU AI Workflow — 单片机 AI 辅助开发「六步法」

> 让 AI 真的能陪你把一个单片机项目做完，而不是写几段代码就跑。

用 AI 做单片机项目，最常见的失败不是代码不会写，而是：**跳步、丢上下文、忘了引脚、做到一半不知道自己在哪一步**。

这个仓库把「需求 → 选型 → 拆解 → 接线 → 编程 → 联调」六个阶段固化下来，每一阶段有固定的产物和验收标准，
AI 在每一步开工前先给方案、等你确认，做完一步才走下一步。

## 它解决什么

| 没有这套东西 | 有这套东西 |
| --- | --- |
| 你说"帮我做个温控风扇"，AI 直接开始写 `main.c` | 先问清楚要采集什么、控制什么、本地怎么交互，产出功能清单 |
| 写着写着引脚对不上，回头改 | 引脚在 S4 一次定死，S5 直接读文档，**不再反问你** |
| 7 个模块一起写，报错不知道错在哪 | 一次只做一个模块，独立验证通过才做下一个 |
| 本地还没跑通就上云，出错分不清是逻辑还是网络 | **本地闭环验收通过后，才允许碰通信** |
| 换个会话就忘了做到哪 | 扫产物文件自动推断进度，台账辅助 |

## 六步法

| 步 | 名称 | 产物 |
| --- | --- | --- |
| S1 | 需求分析 | `[系统]需求功能清单.md` |
| S2 | 硬件选型 | `[系统]硬件选型清单.md`（PCB 版加后缀） |
| S3 | 功能拆解 | `[系统]功能拆解文档.md` |
| S4 | 硬件搭建 | `[系统]硬件搭建文档.md`（引脚分配 + 接线） |
| S5 | 模块编程 | `Module/bsp_*.c/.h` + `main.c` + `[系统]模块编程记录.md` |
| S6 | 功能联调 | `[系统]功能联调报告.md` |

关键设计：

- **S5 的输入锁定**：模块顺序从 S3 的「二、硬件模块清单」读，引脚从 S4 的「四、引脚分配速查」读，**绝不反问用户**
- **本地优先**：本地模块全部通过 → 生成不含通信的 `main.c` → 拔掉 WiFi 仍能完整运行 → 才做通信模块
- **主控是改出来的**：先拼起来跑通，再对照需求找不合理处逐条改，不是一次生成完美版本

## 快速开始

### 方式一：零安装（最省事）

1. 克隆仓库到任意位置
2. 打开 `AGENTS.md`，把里面的路径改成你本机的实际路径
3. 把这个 `AGENTS.md` 复制到你打算开发项目的文件夹
4. 在那个文件夹里对 AI 说：**「按六步法做，我想做个智能温控风扇」**

不需要装任何东西，但每次要明确说"按六步法做"。

### 方式二：安装为 skill（能自动触发）

**Windows：**

```powershell
.\install.ps1
```

**macOS / Linux：**

```bash
chmod +x install.sh
./install.sh
```

脚本会做两件事：

1. 把 `orchestrator/` 复制到 `~/.workbuddy/skills/mcu-project-orchestrator/`
2. 把里面的 `{{AI_SKILL_ROOT}}` 占位符替换成你本机 `AI-Skill/` 的真实绝对路径

装完之后，在**任何文件夹**里说「我想做个智能温控风扇」，它就会自动进流程。

> 已安装过要重装：`.\install.ps1 -Force` 或 `./install.sh --force`

## 工具链要求

| 项 | 要求 |
| --- | --- |
| IDE | 支持 skill 的 AI IDE（CodeBuddy / Qoder / 类似产品） |
| 编译工具 | **STM32Cube 扩展**（内含 CubeMX）+ CMake |
| 芯片 | 默认 STM32F103C8T6，其他型号需自行改引脚参考表 |
| 库 | **HAL**（LL 按 HAL 处理）；标准库仅限遗留工程 |
| 编译烧录 | **本仓库不涉及**。你自己的工具编译烧录，AI 只看你回报的现象 |

> ⚠️ 本仓库默认 **HAL + CMake**。如果你用 Keil + 标准库，需要按 `orchestrator/references/toolchain-baseline.md` 里的换算表调整。

## 设计上的几个取舍

**为什么编排器只有一个，其他 skill 不注册？**

如果 7 个都注册，你说"帮我写个 DHT11 驱动"可能直接命中驱动生成器，绕过整个流程——出来的代码不知道引脚从哪来。
只注册编排器，入口唯一，所有请求都从它进去。

**为什么每步都要确认？**

不确认就动手，等于让 AI 替你做技术决策。方案卡把"本步目标 / 关键决策点 / 将产出 / 需要你回答"摆出来，你点头才执行。
嫌烦可以说「不用问了」切批量模式——但 S5 不会批量，因为每个模块都要你真机验证。

**为什么要限制读取？**

7 个模块每个都重读一次驱动生成器规则，会多烧约 6 万 token，内容还完全一样。
所以规定：`stm32-driver/SKILL.md` 整个 S5 只读一次，`stdperiph-guide.md` 在 HAL 工程里不读。

## 已知限制

- **不含课件原文**：`AI-Skill/course-notes/` 里的内容整理自一套第三方免费课程，版权归原作者，本仓库不附带，只保留一份说明
- **不执行编译烧录**：AI 生成代码、做静态自检；编译报错和硬件现象由你验证后回报
- **看不到实物**：接线问题只能通过"现象 + 排查清单"反推
- **只支持 STM32F103 系**：引脚参考表和驱动模板都是这个系列的
