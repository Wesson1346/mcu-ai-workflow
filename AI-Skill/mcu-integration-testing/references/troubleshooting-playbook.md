# 跨模块问题排查手册

联调阶段的问题九成落在下面五类。**按顺序分流，一次只改一处**，改完立刻重测那一条用例。

## 分流 0：先问三个问题

1. **单独跑还能通吗？**（把 `MODULE_TEST` 改回该模块）——能通说明是"一起跑才出问题"，走分流 3
2. **上一次改动是什么？**——先回滚那处改动再验证，不要在当前状态上继续叠加
3. **现象是稳定复现还是偶发？**——偶发优先怀疑时序/中断/电源，稳定复现优先怀疑逻辑/引脚

## 分流 1：采集类异常（读数不对）

| 现象 | 首要怀疑 | 排查动作 |
| --- | --- | --- |
| 恒为 0 / 恒定值 | 传感器无响应；引脚接错；初始化没调用 | ① 确认该模块 Init 在主循环前被调用 ② 用串口打印原始字节 ③ 对照硬件搭建文档核对引脚 |
| 偶发跳变 | 时序余量不足；中断打断；线太长 | ① 关键时序段关中断 ② 缩短信号线 ③ 降低采样频率 |
| 有规律偏移 | 校准/换算系数问题 | 记录偏差值；判断是否可接受；必要时加补偿 |
| 首次读数对、之后不对 | 缓冲区未清；状态机没复位 | 每次读取前清状态；确认读完复位 |
| DHT11 类单总线读不到 | 响应三段时序不匹配；起始信号处理错 | 按 `stm32-driver/references/sensor-catalog.md` 的 DHT11 五条坑逐条核对 |

## 分流 2：执行类异常（动作不对）

| 现象 | 首要怀疑 | 排查动作 |
| --- | --- | --- |
| PWM 完全无输出 | 引脚不在定时器通道；`HAL_TIM_PWM_Start` 未调；比较值没更新 | ① 核对引脚复用表 ② 确认启动了 PWM 通道 ③ 确认 `__HAL_TIM_SET_COMPARE` 有调用 |
| PWM 有输出但调速不明显 | 频率不合适；占空比映射错 | 风扇类常用 10–20kHz；检查映射区间 |
| 开关类动作不响应 | GPIO 模式配错（推挽/开漏）；电平逻辑反了 | 万用表量引脚电平；确认是低电平有效还是高电平有效 |
| 动作后复位 | 电机/继电器反向电动势干扰；电源带不动 | 加续流二极管；单独给执行器供电；共地 |

## 分流 3：单独能跑、一起就废（最常见）

| 现象 | 首要怀疑 | 排查动作 |
| --- | --- | --- |
| 加了新模块，旧模块失效 | **引脚冲突** | 回查硬件搭建文档「三、检查引脚冲突」7 项；重点查定时器/串口是否被抢占 |
| 加了显示后采集错 | 显示耗时挤占时序 | 显示降到 100ms 一次；关键时序关中断 |
| 加了通信后整体卡顿 | MQTT 解析阻塞主循环 | 用非阻塞 `ESP8266_GetIPD(0)`；解析放低频任务 |
| 加了按键后数值乱跳 | 按键扫描用了长延时 | 改节拍式扫描；消抖用计数器不用 `HAL_Delay` |
| 中断里做的事太多 | 中断服务函数里跑长逻辑 | 中断只置标志，逻辑放主循环 |

## 分流 4：系统级不稳定

| 现象 | 首要怀疑 | 排查动作 |
| --- | --- | --- |
| 随机复位 | 电源电流不足（ESP8266 发射瞬间拉低电压） | 电源加大电容（100–470µF）；单独给 ESP8266 供电；用万用表看复位瞬间电压 |
| 跑几分钟就死 | 内存泄漏（MQTT 库用 malloc） | 检查 `MQTT_MallocBuffer` 对应的释放；减少上报频率 |
| 上电偶发不启动 | 模块上电时序；传感器初始化太快 | 上电后 `DelayMs(100)` 再初始化 |
| 屏幕偶发花屏 | I2C 速率过高；线太长 | 降低 I2C 速率；缩短线 |
| 有时能连云有时不能 | WiFi 信号弱；Token 过期 | 看 RSSI；检查 `et=` 过期时间戳 |

## 分流 5：功能与需求不符

| 现象 | 归因 | 处理 |
| --- | --- | --- |
| 测出来"能用"，但不确定算不算达标 | 需求写得含糊 | **回 S1** 把验收标准写具体（什么数值、什么现象） |
| 需求清单里有，代码里找不到 | 漏做 | 补做，按模块编号插回顺序表 |
| 行为与需求描述相反 | 理解偏差 | 回 S1 对齐定义 |
| 多个需求互相冲突 | 需求设计问题 | 回 S1 做取舍 |

---

## 排查纪律

1. **一次只改一处**，改完立刻重测
2. **先回滚再前进**：如果上一次改动引入了问题，先撤掉它
3. **留下证据**：串口打印 + 现象描述，比"好像是"有用一百倍
4. **不要在 `while(1)` 里到处加 `HAL_Delay` 试**——那会制造新问题
5. 每解决一个，写进联调报告「问题与修复记录」，标明退回哪一步
