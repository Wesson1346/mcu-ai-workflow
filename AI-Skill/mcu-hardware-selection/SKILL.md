# 单片机系统硬件选型（生成硬件清单）

## Overview

将一份**系统功能清单**（来自 mcu-requirement-analysis 或用户直接提供）逐项映射为对应的**硬件模块**，为每个模块确定**型号、接口类型**，最终产出一份完整的《系统名称硬件选型清单.md》文档。该文档是后续功能拆解、电路搭建、模块编程的输入，保证每个功能都有对应硬件支撑。

生成清单前必须**先确认搭建方式**，并按搭建方式输出**互不混用**的对应清单：
- **面包板搭建** → 只输出面包板对应的元器件清单（模块 + 面包板套装等）
- **PCB 板搭建** → 默认按"模块化直插底板"模式，输出"模块清单 + 载板物料清单"

## 核心原则

- 硬件选型不是越贵越好，**够用就行**，能满足功能即可
- **资料多的优先**：网上教程多，出问题好查
- **常用的优先**：不选小众模块，除非非它不可
- **接口通用的优先**：I2C/SPI/UART 优先，方便接线
- 选型前确认**供电电压匹配**（STM32 是 3.3V 逻辑）
- **搭建方式决定清单内容**：面包板只列面包板器件，PCB 按 PCB 分支处理，两种清单不混用
- **PCB 搭建默认"模块化直插底板"**：PCB 只是布线底板，模块经排母/排针直插、走线代替杜邦线，主控用最小系统板插底板，核心板 USB 供电，PCB 上不画电源/驱动电路。仅当用户明确要求自绘电路（学驱动原理/裸片最小系统）时，才在"选型说明"中客观陈述其它选项
- **有等价方案时优先选更模块化**：同一执行器（如小风扇）常存在"裸器件+驱动"与"模块化直驱"两种等价方案，选型时**优先选更模块化的方案**（模块化直驱接线简单、省去驱动电路），仅在用户明确要求（如为了学驱动原理）时才选"裸器件+驱动"
- **只做型号选择，不分配引脚**：引脚分配和冲突检查放到"系统电路搭建"阶段

## 工作流程：功能→硬件映射法

严格按照以下五步执行。每完成一步，将结果告知用户，征求确认后再进入下一步。

### 第一步：解析功能清单

**输入方式（两种都支持）**：
- 方式 A：用户提供功能清单 md 文档路径，用 Read 读取
- 方式 B：用户直接在对话中粘贴功能清单文本

从功能清单中提取出**每一项功能**，识别每项功能涉及的要素：

| 功能要素 | 含义 | 对应的硬件方向 |
| --- | --- | --- |
| 数据采集 | 测温度/湿度/距离/光照等 | 传感器 |
| 显示输出 | OLED/LCD/数码管等 | 显示屏 |
| 执行器控制 | 风扇/电机/舵机/继电器等 | 执行器+驱动 |
| 本地交互 | 按键、旋钮、触摸等 | 输入器件 |
| 通信 | WiFi/蓝牙/串口等 | 通信模块 |
| 报警提示 | 蜂鸣器/LED 灯等 | 报警器件 |

**输出**：整理成"功能 → 硬件方向"的映射草表，告知用户。

### 第二步：确认搭建方式

开始映射硬件前，必须先确认用户将以哪种方式搭建：

- 若用户在需求中已明确（如说"打样 PCB""面包板验证"），直接采用并告知用户
- 若未明确，**必须主动询问**用户使用哪种搭建方式：**面包板** 还是 **PCB 板**（只问一次，用选项让用户快速选择）

**分支规则**：
- 搭建方式 = **面包板**：后续按面包板分支执行，只生成面包板搭建对应的元器件清单，**不混入 PCB 相关内容**
- 搭建方式 = **PCB 板**：按 PCB 分支执行，默认"模块化直插底板"方案（见核心原则），输出含"模块清单 + 载板物料清单"的 PCB 版清单

**输出**：把确认的搭建方式告知用户，后续所有步骤严格按该分支执行，不再变更。

### 第三步：功能 → 硬件映射

逐项将功能对应到具体硬件模块，使用 `references/common-modules.md` 的**常用外设选型库**挑选型号。映射规则：

```
① 数据采集功能 → 传感器模块
② 显示功能 → 显示屏模块
③ 执行器功能 → 执行器 + 驱动电路（注意电流匹配）
④ 本地交互功能 → 按键/旋钮/触摸输入
⑤ 通信功能 → WiFi/蓝牙/串口模块
⑥ 报警功能 → 蜂鸣器/LED
```

**按搭建方式分支**：
- **面包板分支**：只做上述功能→模块映射，无需其它内容
- **PCB 分支**：功能→模块映射结果与面包板分支**完全一致**（同一批模块经排母/排针直插）；额外参照 `references/pcb-board-materials.md` 为底板补充**载板物料**（排母/排针、接线端子、直插小件等）

**重要映射技巧**：
- 一个硬件模块可能对应多个功能（如 OLED 同时显示温度、转速、模式）
- 有些功能不需要额外硬件（如"阈值设置"复用按键+OLED，"App远程控制"复用WiFi模块）
- **执行器先判断"器件形态"**：同一种执行器（如小风扇）有"裸器件"和"模块化器件"两种形态：
  - **方案A 裸器件 + 驱动电路**：如裸 5V 风扇 + S8050 三极管（或 L298N/ULN2003）。工作电流大，GPIO 电流不够（约 20mA），必须另配驱动。教学价值高，能讲透"为什么 GPIO 不能直驱大功率器件、三极管如何做开关"的原理
  - **方案B 模块化器件（自带驱动）**：如自带 MOS/三极管驱动电路的小风扇模块，可直接接 GPIO / PWM。省去搭驱动电路，接线方便，但驱动电路被封装（黑盒化）
  - **有等价方案时优先选方案B（更模块化）**：核心硬件清单中只列一种（更模块化的方案），不双方案并列。仅在用户**明确要求学驱动原理**时才选方案A（裸器件+驱动）。如需在文档中说明两种方案差异，放在"选型说明"里客观陈述，**不写倾向性"选型建议"**

### 第四步：选型补充与校对

完成功能映射后，按搭建方式补齐必备项（**主控、驱动、电源都合并进"核心硬件清单"表，不单列章节**）：

1. **主控芯片**：默认 STM32F103C8T6 最小系统板（最常用、资料最多、引脚够用），面包板与 PCB 两种方式通用
2. **驱动电路**：仅在选了"裸器件+驱动"方案时才补（如裸风扇需 S8050 三极管、步进电机需 ULN2003）；若选的是"模块化直驱"方案则无需驱动电路
3. **按搭建方式补充**：
   - 面包板：面包板、杜邦线、电源适配器、必要时稳压模块
   - PCB（模块化直插底板）：排母/排针、接线端子、电位器/按键等直插小件、可选固定件；默认核心板 USB 供电，**不添加电源座/开关/LDO 等电源电路**（若 ESP8266 等实测供电不稳，才在选型说明中提示可加一片 AMS1117-3.3）

**校对清单**（逐项打勾）：
- [ ] 功能清单里的每一项功能都有对应硬件
- [ ] 搭建方式已确认，清单内容与搭建方式一致、未混入另一种方式的内容
- [ ] 无遗漏、无多余
- [ ] 供电电压匹配（STM32 3.3V 逻辑）
- [ ] 加分功能与舍去功能核对（舍去的不需要硬件）

### 第五步：输出 md 文档

按搭建方式选择对应模板生成并保存硬件选型清单：

- **面包板搭建**：使用 `assets/hardware-list-template.md`
- **PCB 板搭建**：使用 `assets/hardware-list-template-pcb.md`

1. 使用 Write 保存到**当前工作目录**（用户项目根目录）
2. 文件命名：面包板版 `[系统名称]硬件选型清单.md`；PCB 版 `[系统名称]硬件选型清单（PCB版）.md`
3. **只写型号/接口，不分配引脚**（引脚留给系统电路搭建阶段）
4. **文档结构**：主控、驱动、电源都合并进"核心硬件清单"表，不单列章节；"选型说明"只客观陈述方案差异与注意事项，**不写倾向性"选型建议"**
5. **不含参考价列**：输出清单不包含参考价格列，也不写"合计参考价"；选型库中的价格仅作内部选型参考，不进入输出文档
6. **固定备注**：在"核心硬件清单"表格上方附加固定备注：元器件选型是根据系统所需功能推荐的一种常见的模块，大家可以根据需求，自行修改对应的模块即可
7. 保存后告知用户文件路径，并简要总结清单要点

## 注意事项

- **输入必须是功能清单**：如果用户只有模糊想法（还没有功能清单），先引导用户用 `mcu-requirement-analysis` 生成功能清单，再进入本 skill
- **必须确认搭建方式**：进入映射前先确认面包板/PCB，用户未说明时必须主动询问一次
- **清单不混用**：面包板只输出面包板清单；PCB 输出 PCB 版清单。生成内容不得同时包含两种搭建方式的器件
- **只做型号选择**：本 skill 绝不分配引脚、不做接线图，那些属于"系统电路搭建"阶段
- **不越贵越好**：每个模块选够用的、资料多的型号即可，不追求高端
- **供电电压匹配**：STM32 是 3.3V 逻辑，选型时标注模块供电要求（如风扇用 5V + 驱动隔离，ESP8266 必须 3.3V）
- **文档输出是必须的**：每次执行完五步法，一定要用 Write 把硬件清单保存为 md 文档，不能只在对话里输出
- 若当前工作目录存在同名文件，先询问用户是否覆盖，或生成带日期后缀的文件名
