# OneNET 平台侧配置（上云前必做）

> 来源：课件第 14、15、16 章（经 IMA 读取原文后整理）
> **分工**：本文档讲**平台控制台怎么配**；代码层面的 4 个坑见 `onenet-guide.md`。
> 两者配合看：先按本文档把平台配好、用 MQTT.fx 验证通，再生成/调试单片机代码。

## 一、一张表管住三个地方

上云所有问题的根源，都是**同一个名字在三个地方写得不一样**：

| 地方 | 在哪填 | 典型错法 |
| --- | --- | --- |
| 平台 | OneNET 控制台 → 物模型 | 标识符写成 `Temp` |
| 代码 | `onenet.h` / 上报 JSON | 写成 `temp` |
| App | 设置页 / 界面绑定 | 又写成 `Temp` |

**课件原话**：标识符大小写、拼写差一个字数据就不显示（平台 `Temp` vs 代码 `temp` → 收不到）。

**排查顺序**（课件给的）：网络 → Topic 与标识符 → App 一致性。
不要一上来就怀疑代码，先确认平台侧的标识符到底叫什么。

## 二、平台配置五步（课件 14）

### ① 注册
`https://iot.10086.cn/` → 进开发者中心。

### ② 创建产品（4 个选项别选错）
| 配置项 | 选什么 |
| --- | --- |
| 接入协议 | **MQTT** |
| 数据协议 | **OneJSON** |
| 联网方式 | **WIFI** |
| 开发方案 | **自定义** |

课件明确：这 4 项是带 ★ 的必填项，选错后面全对不上。

### ③ 创建设备
在产品下建设备并命名。**这个设备名就是代码里的 `ONENET_DEVID`**。

### ④ 创建物模型（课件给的示例标识符）

| 标识符 | 数据类型 | 用途 |
| --- | --- | --- |
| `alarm` | bool | 报警状态 |
| `fan_on` | bool | 风扇开关 |
| `mode` | bool | 模式 |
| `fan_duty` | int32 | 风扇档位 |
| `temp` | int32 | 当前温度 |
| `temp_high` | int32 | 上限阈值 |
| `temp_low` | int32 | 下限阈值 |

> 这是课件示例，**实际以你自己在控制台创建的为准**。创建时就把名字定死，后面代码和 App 都用它。

### ⑤ 生成 Token
用 OneNET 平台的 Token 工具生成，参数含义：

| 参数 | 填什么 |
| --- | --- |
| `res` | `products/{产品id}/devices/{设备名}` |
| `et` | 一个**大于当前连接时刻**的时间戳（秒） |
| `key` | 设备密钥 |
| `method` | `md5` |
| `version` | `2018-10-31` |

**Token 有有效期，过期即掉线**——这是"昨天还好、今天连不上"最常见的原因。

## 三、先不上单片机：用 MQTT.fx 验证平台

这一步能省掉大量排查时间。**平台没配通就别碰单片机代码**。

| 参数 | 填什么 | 要不要改 |
| --- | --- | --- |
| Broker 地址 | 见下方「参数矛盾」一节 | 按控制台 |
| 端口 | `1883` | 不改 |
| Client ID | **设备名** | 改 |
| User Name | **产品 id** | 改 |
| Password | **Token** | 改 |

课件原话：Broker 和端口保持不变，**只改 Client ID、User Name、Password 三项**。

**看连接状态灯**：小红灯 = 连接失败（查参数）；小绿灯 = 连接成功。

连通后做两件事：

1. **测上行**：向 `$sys/{产品id}/{设备名}/thing/property/post` 发布
   `{"id":"1","params":{"temp":{"value":28}}}`
   → 平台「设备详情 → 设备调试」应能看到 `temp` 变成 28
2. **测下行**：订阅 `$sys/{产品id}/{设备名}/thing/property/set`，
   在「设备调试 → 应用模拟器」里选一个 bool 属性下发 `true`
   → MQTT.fx 应收到报文

这两步通了，说明平台、Token、物模型、Topic 全对。剩下只是单片机代码的问题。

## 四、代码侧要改的 5 处（课件 15）

用 `stm32-driver` 生成 OneNET 代码后，**必须改这 5 处**，否则连不上或数据不显示：

| # | 改什么 | 去哪找 |
| --- | --- | --- |
| ① | WiFi 名称 + 密码 | 你自己的路由器 |
| ② | MQTT 设备名 / 产品 id / Token | OneNET 控制台 |
| ③ | 上报 Topic | 物模型 Topic 列表 |
| ④ | 接收 Topic | 物模型 Topic 列表 |
| ⑤ | 物模型标识符 | 与平台定义**完全一致** |

对应本仓库文件：
- ①②→`Module/esp8266.c` 顶部配置区（`YOUR_WIFI_SSID` / `YOUR_WIFI_PWD`）
- ②③④⑤→`Module/onenet.h` 顶部配置区（`YOUR_PROID` / `YOUR_DEVID` / `YOUR_TOKEN`，Topic 由宏自动拼接）

## 五、下行怎么处理（课件 16）

| 要点 | 说明 |
| --- | --- |
| 订阅一次即可 | 设备启动/连上平台时订阅 `.../thing/property/set` 一次，**长期有效，不用轮询** |
| 解析 `params` | 报文结构：`{"id":"指令编号","params":{"Alarm":{"value":true}}}` |
| 在回调里执行 | 判断标识符 → 判断值（`true` 开 / `false` 关）→ 置位复位 GPIO 或调模块驱动 |
| 可选回传 | 执行完可以把新状态再上报一次，让 App 同步 |
| 数据点分工 | **数值型**（温度/湿度）以上报为主；**开关型**（报警/LED）才是下发常客 |

## 六、三层验证顺序（课件 15）

```
第一层 串口：看到 "WiFi Connected" → "MQTT Connected"
第二层 平台：设备列表显示「在线」，且属性值在刷新
第三层 App ：显示的值与实物一致
```

哪一层断了就停在哪一层查，不要跳层。

## 七、⚠️ 课件内部两处矛盾（必须知道）

### 1. Broker 域名，两篇写法不同

| 出处 | 写法 |
| --- | --- |
| 课件 14 | `mqts.hecloud.com` |
| 课件 15 | `mqts.heclouds.com` |

两处不一致，且都像是笔误（OneNET 的 MQTT 接入域名通常是 `mqtts.` 开头、`heclouds.com` 结尾）。

**处理原则**：不要照抄课件，**以控制台「设备详情 → 连接参数」里显示的地址为准**，那个是唯一权威。
连不上时先怀疑这里。

### 2. 物模型标识符，两套对不上

| 出处 | 标识符 |
| --- | --- |
| 课件 14 | `alarm`、`fan_on`、`mode`、`fan_duty`、`temp`、`temp_high`、`temp_low` |
| 课件 16 | `Alarm`、`Led` |

`Led` 在 14 章那份物模型清单里**根本不存在**，大小写也不一致。

**处理原则**：以你自己在控制台创建的物模型为准。如果只建一份，就用 14 章那套（更完整），
把 16 章的 `Alarm`/`Led` 理解为"报警和 LED 两个开关型属性"的举例，映射到 `alarm` 和你自己的 LED 标识符上。
