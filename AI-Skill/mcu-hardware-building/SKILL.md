# 单片机系统硬件搭建（生成引脚分配与接线文档）

## Overview

将一份**硬件模块清单**（来自 mcu-hardware-selection 或 mcu-functional-decomposition）分配到 STM32 的具体引脚上，并给出完整的**接线说明**（每个模块的 VCC/GND/信号怎么接、接线总表、整体接线图、注意事项）。产出物是一份《系统名称硬件搭建文档.md》，一步到位，作为后续模块编程写代码的依据。

## 核心原则

- **引脚分配 + 接线一起完成，不写驱动代码**：驱动代码属于模块编程阶段
- **只给信号引脚，并说明电源接线**：信号引脚分配 + VCC/GND 接哪个电源轨，一步到位
- **先供电、再信号**：先确定主控和电源轨，再逐个模块接线
- **特殊功能优先**：PWM 用 TIM 通道引脚，串口用 USART，I2C 用 SCL/SDA，ADC 用模拟输入引脚
- **普通 GPIO 灵活选**：按键、蜂鸣器等纯数字 IO 用任意空闲 GPIO
- **一个引脚只能分给一个模块**：重复占用即为冲突，必须调整
- **执行器方案以硬件选型清单为准**：裸器件+驱动（如 S8050）或模块化直驱，接线方式不同

## 工作流程：硬件搭建四步法

严格按照以下步骤执行。每完成一步，将结果告知用户，征求确认后再进入下一步。

### 第一步：梳理硬件模块清单

**输入方式（两种都支持）**：
- 方式 A：用户提供硬件选型清单 / 功能拆解文档 md 路径，用 Read 读取
- 方式 B：用户直接在对话中粘贴硬件模块列表

**操作**：
1. 读取清单，列出每个硬件模块及其接口类型（单总线/I2C/PWM/GPIO/ADC/USART）
2. 区分三类引脚需求：
   - **特殊功能引脚**：需绑定外设（PWM→TIM、USART→串口、I2C→SCL/SDA、ADC→模拟输入）
   - **普通 GPIO**：任意空闲引脚（按键、蜂鸣器、单总线）
   - **无信号模块**：电源/接线、纯软件复用功能
3. 统计需要的引脚和特殊外设数量，判断 STM32F103C8T6 是否够用

**输出**：一张"模块 → 接口 → 引脚需求类型"的梳理表，告知用户。

### 第二步：分配引脚

使用 `references/common-pin-mapping.md` 的 **STM32F103C8T6 引脚资源参考**，逐模块分配引脚。分配顺序建议：

```
① 先分特殊功能引脚（PWM/USART/I2C/ADC），它们绑定外设，不能乱选
② 再分普通 GPIO（按键/蜂鸣器/单总线），从剩余空闲引脚里挑
③ 最后核对每个模块，确保没有两个模块用同一个引脚
```

**关键分配规则**：
- **PWM**：TIM 通道引脚，如 TIM2_CH1→PA0、TIM3_CH1→PA6
- **USART**：USART1→PA9(TX)/PA10(RX) **保留给单片机调试打印（printf）**；模块（WiFi/蓝牙等）优先使用 USART2→PA2/PA3 或 USART3→PB10/PB11，一个串口只给一个模块
- **I2C**：硬件 I2C1→PB6/PB7；OLED 常用软件 I2C，任意两 GPIO 模拟 SCL/SDA
- **ADC**：ADC1 通道 PA0~PA7、PB0、PB1，模拟输入不能和数字功能冲突
- **单总线/普通 GPIO**：任意空闲引脚

**执行器接线方式**（重要）：
- **裸器件 + 驱动**（如裸风扇 + S8050）：只给**驱动控制引脚**（三极管基极），如 PA0→S8050 基极；驱动电路的电源/负载接线单独说明
- **模块化直驱**（如自带驱动的风扇模块）：信号端直接接 STM32 引脚，电源按模块供电要求

### 第三步：检查引脚冲突

```
□ ① 是否有两个模块用了同一个引脚？（重复占用 = 冲突）
□ ② PWM 是否都用了 TIM 通道引脚？
□ ③ 串口是否每个模块独享一个 USART？
□ ④ I2C 的 SCL/SDA 是否成对且不冲突？
□ ⑤ ADC 引脚是否没有复用成数字功能？
□ ⑥ 引脚编号是否与 STM32F103C8T6 实际引脚定义一致？
□ ⑦ 是否用到了 JTAG/SWD 调试引脚（PA13/PA14/PA15、PB3/PB4）？若用作普通 GPIO，必须在文档注意事项注明"需禁用 JTAG"，并在代码初始化时调用对应 API（均保留 SWD）：HAL 库用 `__HAL_AFIO_REMAP_SWJ_NOJTAG()`，标准库用 `GPIO_PinRemapConfig(GPIO_Remap_SWJ_JTAGDisable, ENABLE)`；PA13/PA14（SWD）尽量不做 GPIO
```

发现冲突时，调整某个模块的引脚重新分配，直到无冲突。

### 第四步：输出硬件搭建文档

**先按搭建方式选模板**（必须与《[系统名称]硬件选型清单》里确定的搭建方式一致）：

| 搭建方式 | 使用模板 | 输出文件名 |
| --- | --- | --- |
| 面包板 | `assets/hardware-building-template.md` | `[系统名称]硬件搭建文档.md` |
| PCB（模块化直插底板） | `assets/hardware-building-template-pcb.md` | `[系统名称]硬件搭建文档.md` |

两个模板的「一~九」章节结构完全相同，其中**「四、引脚分配速查」与「六、接线总表」两节字段必须完全一致**——后续「模块编程」阶段依赖这两节读取引脚，格式错位会导致链路中断。

基于选定模板生成并保存硬件搭建文档：

1. 使用 Write 保存到**当前工作目录**（用户项目根目录）
2. 文件命名：`[系统名称]硬件搭建文档.md`（例如：`智能温控风扇系统硬件搭建文档.md`）
3. 文档结构：搭建依据 → 元器件清单 → 搭建总思路 → 引脚分配速查 → 各模块详细接线 → 接线总表 → 整体接线图 → 接线注意事项 → 验证建议
4. 保存后告知用户文件路径，并简要总结（用了哪些引脚、有无冲突、接线要点）

## 注意事项

- **输入必须是"硬件模块清单"**：如果用户还没有硬件选型/拆解结果，先引导用户用 `mcu-hardware-selection` 生成硬件清单、用 `mcu-functional-decomposition` 生成拆解文档，再进入本 skill
- **执行器方案以硬件选型清单为准**：清单选"裸器件+驱动"还是"模块化直驱"，接线方式就按哪个写，不擅自改
- **搭建方式以选型清单为准**：面包板项目用面包板模板，PCB 项目用 PCB 模板，不得混用（PCB 项目套面包板模板会出现"面包板 830 孔""红轨/蓝轨"等错误内容）
- **供电要写清楚**：每个模块的 VCC 接 3.3V 还是 5V、GND 共地，必须标明；ESP8266 必须 3.3V
- **不写驱动代码**：本文档只讲硬件接线，代码实现见"模块编程"阶段
- **发现冲突必须调整**：不能把两个模块分到同一引脚后还输出，必须改到无冲突
- **文档输出是必须的**：每次执行完四步法，一定要用 Write 把硬件搭建文档保存为 md 文档，不能只在对话里输出
- 若当前工作目录存在同名文件，先询问用户是否覆盖，或生成带日期后缀的文件名
