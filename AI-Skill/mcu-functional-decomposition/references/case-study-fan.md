# 案例：STM32 智能温控风扇系统（完整二步法示例）

本案例展示"功能拆解二步法"的完整过程，作为执行 skill 时的参考。用户提供新系统的需求功能清单 + 硬件选型清单时，按此流程推进。

## 输入

- 需求功能清单：`智能温控风扇系统需求功能清单.md`
- 硬件选型清单：`智能温控风扇系统硬件选型清单.md`（风扇选的是自带驱动的模块化风扇）

## 第一步：提取硬件模块

把需求功能逐项映射到硬件。**模块编号按"单模块编程递加顺序"编排**：先做数据源 DHT11（模块1）与显示 OLED（模块2，兼作后续所有模块的调试窗口），再做执行器风扇（模块3）→ 按键（模块4）→ 蜂鸣器（模块5）→ 电位器（模块6），ESP8266 通信（模块7）依赖数据最多、放最后上云联调。本例需求编号恰与模块编号巧合一致，一般系统两者会不一致，以映射表对应为准。

| 需求功能 | 对应硬件 | 模块编号（=编程顺序） |
| --- | --- | --- |
| ① 温湿度采集 | DHT11 传感器 | 模块1 |
| ② OLED 显示 | 0.96寸 OLED 屏幕 | 模块2 |
| ③ 风扇自动调速 | 自带驱动的风扇模块 | 模块3 |
| ④ 本地按键交互 | 6×6 轻触按键 ×3 | 模块4 |
| ⑤ 温度阈值设置 | （复用按键+OLED，无新硬件） | — |
| ⑥ 超温报警 | 有源蜂鸣器 | 模块5 |
| ⑦ 手动调速 | 10K 旋转电位器 | 模块6 |
| ⑧ WiFi 通信 | ESP8266 ESP-01S | 模块7 |
| ⑨ 手机 App 远程控制 | （纯软件，复用 ESP8266） | — |

**硬件模块清单（本系统共 7 个硬件模块，编号即编程递加顺序）：**

```
模块1：DHT11 温湿度传感器   ← 先做：数据源
模块2：0.96寸 OLED 显示屏   ← 再做：把数据显示出来，兼作调试窗口
模块3：自带驱动的风扇模块   ← 再做：执行器
模块4：6×6 轻触按键 ×3      ← 再做：交互
模块5：有源蜂鸣器            ← 再做：报警
模块6：10K 旋转电位器        ← 再做：手动输入
模块7：ESP8266 ESP-01S WiFi模块 ← 最后做：数据上云+远程控制
```

## 第二步：写模块卡片

模块卡片按模块编号（=编程顺序）逐张书写：

```
模块1：温度采集
├─ 硬件型号：DHT11（单总线）
├─ 功能描述：每隔1秒读取环境温度；输出温度值，供 OLED 显示、主控逻辑判断和 OneNET 上传使用
└─ 验证方法：串口打印温度，用手捏传感器看数值明显变化

模块2：OLED显示
├─ 硬件型号：0.96寸 SSD1306（I2C）
├─ 功能描述：显示温度、风扇转速、当前模式（自动/手动）、温度阈值；读取各模块数据并刷新显示，兼作后续各模块的调试窗口
└─ 验证方法：先显示固定文字确认正常，再确认温度等数值能实时变化

模块3：风扇PWM控制
├─ 硬件型号：自带驱动的风扇模块（PWM）
├─ 功能描述：接收占空比（0~100%）控制风扇转速；自动模式由主控按温度给占空比，手动模式由电位器（模块6）给定
└─ 验证方法：设50%占空比，看风扇是否转；改变占空比看转速变化

模块4：按键输入
├─ 硬件型号：6×6 轻触按键 ×3（GPIO）
├─ 功能描述：检测3个按键的按下事件，带软件防抖；按键1切模式、按键2/3调阈值；结果作为主控逻辑的用户指令
└─ 验证方法：按按键，串口打印对应的按键编号

模块5：蜂鸣器报警
├─ 硬件型号：有源蜂鸣器（GPIO）
├─ 功能描述：温度超上限阈值时发出报警；由主控逻辑判断触发，输出电平控制蜂鸣器响/停
└─ 验证方法：GPIO拉高，蜂鸣器响；拉低，蜂鸣器停

模块6：电位器输入
├─ 硬件型号：10K旋转电位器（ADC）
├─ 功能描述：读取电位器旋钮位置并转成数值（0~4095/0~100）；手动模式下作为风扇转速的给定值
└─ 验证方法：旋转电位器，串口打印数值随之变化

模块7：WiFi通信
├─ 硬件型号：ESP8266 ESP-01S（USART）
├─ 功能描述：连接 WiFi 接入 OneNET 云平台；上传温度等数据，接收 App 下发的开关/调速/切模式指令
└─ 验证方法：串口打印 "WiFi Connected"；OneNET 平台能看到设备上线和数据更新
```

## 第三步：模块关系图

```
                     ┌──────────────┐
   模块1 DHT11 ──────▶│              │──▶ 模块2 OLED（显示）
   模块4 按键  ──────▶│   主控逻辑     │
   模块6 电位器 ─────▶│  (联调阶段实现) │──▶ 模块3 风扇（PWM）
   模块7 ESP8266 ◀───▶│              │──▶ 模块5 蜂鸣器（报警）
  （App指令/上传数据） │              │
                     └──────────────┘
```

**数据流总结**：传感器（模块1）提供温度 → 主控逻辑判断 → 控制风扇（模块3）、触发蜂鸣器报警（模块5）→ 状态显示（模块2）→ 温度上传云平台（模块7）→ App 指令再回主控（切模式/调速/开关）。（完整主控逻辑在功能联调阶段实现）

## 第四步：自检

- ✅ 模块数量正确（7个硬件 = 7个模块），无遗漏
- ✅ 每个模块可独立测试
- ✅ ⑤阈值设置、⑨App控制为纯软件/复用，未混入硬件模块
- ✅ 模块编号按"编程递加顺序"编排（数据源/显示在前，执行器/按键/报警/电位器居中，WiFi 最后），映射表能对上需求功能编号（①②③④⑥⑦⑧）
- ✅ 模块关系清楚，能说清数据流向

## 小结

功能拆解二步法：提取硬件模块 → 写模块卡片，再补一张模块关系图说明协作关系。

核心原则：
- 一个硬件外设 = 一个独立模块
- 模块编号 = 单模块编程递加顺序（先数据源/显示调试窗口，后执行器/交互/报警/手动输入，通信最后上云），每实现一个模块系统就多一项可演示功能
- 纯软件功能不单独成模块
- 只做拆解，不分配引脚、不写驱动代码
