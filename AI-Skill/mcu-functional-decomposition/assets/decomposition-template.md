# [系统名称] — 功能拆解文档

## 一、拆解依据

基于 [系统名称] 的需求功能清单（[需求功能清单文档名]）和硬件选型清单（[硬件选型清单文档名]），把系统拆解为一个个可独立开发、独立测试的硬件模块。本文档只做功能拆解，不分配引脚、不写驱动代码（引脚分配和电路搭建见"系统电路搭建"，代码实现见"模块编程"阶段）。

> **说明：模块编号 = 单模块编程实施顺序**（从易到难、层层递加，每实现一个模块，系统即可独立演示一项功能），与需求功能清单的编号通过第二节映射表一一对应，二者不一致是正常的。

### 需求功能清单 vs 功能拆解文档（为什么会有两份文档）

很多同学容易把这两份文档搞混，这里用一个对比表说清楚：

| | 需求功能清单 | 功能拆解文档 |
| --- | --- | --- |
| 回答的问题 | "系统要做什么" | "系统由哪些模块组成、怎么配合" |
| 视角 | 用户/需求视角（软件视角） | 开发者视角（硬件视角） |
| 内容 | 用大白话描述功能行为：1秒采集一次、转速0~100%、超温报警 | 把功能落到具体硬件型号上，每个硬件一张模块卡片 |
| 一条功能对应 | 一个功能可能对应多个硬件 | 一个硬件外设 = 一个模块 |
| 纯软件功能 | 正常列为一条功能（如③自动控温、⑧App控制） | 标注"纯软件，无新硬件"，不单独成模块 |

**典型例子**："手动调速"在需求功能清单里只是风扇调速下面的一个子功能描述；但在拆解文档里，它对应独立硬件电位器，单独成为一个模块。

**开发流程中的位置**：需求功能清单 → 硬件选型清单 → 功能拆解文档 → 电路搭建 → 模块编程。简单说：**需求功能清单是"做什么"的目标清单，功能拆解文档是"怎么拆成零件来做"的施工图**。

## 二、硬件模块清单

| 需求功能（保留原始编号） | 对应硬件 | 模块编号（=编程顺序） |
| --- | --- | --- |
| ④ [如 OLED 显示] | [硬件模块] | 模块1 |
| ① [如温度采集] | [硬件模块] | 模块2 |
| ② [功能名称] | [硬件模块] | 模块3 |
| ... | ... | ... |
| [App 远程控制等] | （纯软件，复用[某模块]，无新硬件） | — |

> 模块编号**按"单模块编程递加顺序"编排，不必与需求功能编号一致**（示例：显示模块对调试帮助大，故需求④排为模块1；温度采集是数据源排模块2）。排序参考：数据源/传感器 → 显示（调试窗口）→ 执行器 → 交互按键 → 报警 → 手动模拟量输入 → 通信。每个硬件都有归属、每个需求功能都能在表中找到对应行（纯软件功能用"—"标注）。

本系统共拆出 **N 个硬件模块**（+ M 个纯软件功能，不占模块编号）：

```
模块1：[名称]   ← 先实现
模块2：[名称]   ← 再实现（与模块1组成第一个可演示的里程碑）
...
模块N：[名称]   ← 最后实现
```

## 三、模块卡片

按第二节映射表确定顺序，从模块1起逐张书写（模块编号 = 编程递加顺序，编号小的先独立开发与验证）。每张卡片固定 4 个字段：

### 模块1：[模块名称]

```
模块1：[模块名称]
├─ 硬件型号：[具体型号]（[接口]）
├─ 功能描述：[做什么，含输入→输出、触发条件、数据给谁用]
└─ 验证方法：[怎么确认这个模块是好的]
```

### 模块2：[模块名称]

```
模块2：[模块名称]
├─ 硬件型号：[具体型号]（[接口]）

```

（以此类推，每个硬件一张模块卡片，卡片顺序与第二节映射表的模块编号一致）

## 四、模块关系图

```
                     ┌──────────────┐
   模块X [传感器] ────▶│              │──▶ 模块X [执行器]（[PWM]）
   模块X [交互]  ─────▶│   主控逻辑     │
   模块X [输入]  ─────▶│ (联调阶段实现) │──▶ 模块X [执行器]（[PWM]）
   模块X [通信] ◀───▶ │              │──▶ 模块X [报警]（[GPIO]）
  （指令/上传数据）     │              │
                     └──────────────┘
```

**数据流总结**：[传感器提供数据 → 主控逻辑判断 → 控制执行器/触发报警 → 状态显示 → 数据上传云平台 → App 指令再回主控]。（完整主控逻辑在功能联调阶段实现；图中编号与模块卡片一致）

## 五、拆解自检

- [ ] 模块数量正确，每个硬件一个模块，无遗漏
- [ ] 每个模块可独立测试
- [ ] 纯软件功能未混入硬件模块
- [ ] 模块编号按"编程递加顺序"编排（先数据源/显示，后执行器/交互/报警/通信）
- [ ] 映射表保留需求功能编号，两套编号一一对应、无遗漏
- [ ] 模块关系清楚，能说出数据流向
